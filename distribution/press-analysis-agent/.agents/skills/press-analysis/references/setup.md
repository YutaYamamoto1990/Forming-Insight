# 解析運用の初期設定と接続

配布ルート基準で作業する。開発者個人のPythonパス、テスト時のポート、GH保存場所を別の配布先へ持ち込まない。

## 設定の確認

必要環境はWindows、Rhino 8、対応するHops、GHの依存プラグインと解析エンジン、Python 3.11以降。依存関係を勝手にインストール・更新しない。設定がなければ配布ルートの `defaults/user-config.example.json` から `config/user-config.json` を作成し、分かっている値だけを設定する。既存設定は上書きせず必要な項目だけ更新する。

| 設定 | 用途 |
|---|---|
| `compute_url` | 同じPCのCompute URL。公開サーバーへのアップロードはこの版では行わない |
| `timeout_seconds` | GH応答待ち。既定600秒。利用者指定があればそれを使う |
| `processes.<id>.gh_definition` | 選択プロセスのGHファイル。相対パスは配布ルート基準 |
| `api_key_environment` | 認証が必要な場合の環境変数名。キー自体を会話や実行記録へ出力しない |
| `execution_path_alias_root` | 必要時のみ指定する英数字・空白なしのWindows絶対パス |

`processes/<id>/process.json` は入力ファイルパスと、必要に応じて出力ディレクトリの公開入力名を定義する。別のGHを指定するときは、公開入力名と出力先の前提が合うことを確認する。単にGHファイルを差し替えて新しい解析種類として実行しない。配布後も利用者の明示依頼でプロセスを追加・編集できる。解析中は変更しない。手順は `processes/README.md` を参照する。

## Computeが起動していない場合

設定URLと既存のComputeプロセス、`workspace/services/*/server.json` の記録を照合する。過去のPIDや `status: starting` だけで現在の稼働を断定しない。設定ポートが別プロセスで使われていれば、強制終了せず原因を確認する。

実行依頼の範囲で未起動のローカルComputeを起動してよい。Rhino 8に対応するインストール済み `rhino.compute.exe` を指定し、配布ルートから次を実行する。

```powershell
& ./scripts/start_compute.ps1 -ComputeExe $computeExe -Port $port -ServerTimeoutSeconds $serverTimeout
```

`$port` は設定URLと一致させる。`$serverTimeout` は利用者の応答待ち以上とし、600秒待ちなら標準の660秒を使える。環境変数のマシン全体設定は変えない。

スクリプトは起動開始の記録を返す。出力のlogs配下にあるstdout/stderrを確認し、子のComputeがGrasshopperをロードして待受を開始したことを確認する。起動待ちの上限も設定された待機時間以内とし、エラーや期限到達時は解析を開始しない。接続確認の最終判断はrunnerの `/io` 応答で行う。

既に稼働するComputeを使う場合は再起動や設定変更を勝手に行わない。キーが必要な環境では既存の認証設定を使う。設定が分からなければ確認する。

起動したサービスのPIDとログを利用者に追跡可能な状態で残す。終了する場合は自分が起動したプロセスであることと解析が終了済みであることを照合する。利用者が開いているRhinoや他のComputeは停止しない。

## 日本語・空白を含むパス

共有テストGHで使う外部ソルバーは日本語パスで入力待ちになることが確認されている。作業ルートに該当文字がある場合は、実行前に `execution_path_alias_root` を設定する。明示設定した別名から実行用フォルダーへjunctionを作成するため、データの実体はworkspace内に残る。

既存設定を優先し、不足時は利用可能な利用者Temp配下などに英数字・空白なしのパスを選んでconfigへ記録する。ユーザー名やTempパス自体が条件を満たさず、代替先も不明なら保存先を確認する。GHやソルバー内部のスクリプトを修正して回避しない。

別名はrunごとに作られ、自動削除されない。過去runが状態未確定の間は別名や実行ファイルを削除しない。

## 既存ロックと結果確認

`workspace/.analysis.lock` がある場合は参照先の `exchange/run.json` とログを読む。タイムアウトはソルバー停止を意味しない。状態確認と運用担当者による解除が済むまで、新しい解析を実行しない。

結果を見せる依頼ではサーバーを起動する必要はない。指定runの `raw/` を読み、[SKILL.md](../SKILL.md) の状態判定に沿って案内する。生の結果や過去の実行状態を書き換えて成功に見せない。

同梱GH・資材・cfileはprocess.jsonの配布ルート相対パスから取得する。configのプロセス別指定は任意の上書きであり、空なら同梱原本を使用する。
