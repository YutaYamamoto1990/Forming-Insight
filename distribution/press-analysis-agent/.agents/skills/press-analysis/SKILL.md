# Press Analysis

このSkillは配布フォルダー全体と組み合わせて使う。Skill単独でのコピーは想定しない。`SKILL.md` のあるディレクトリから3階層上が配布ルート。以降のパスとコマンドはそのルート基準とし、呼び出し元の作業ディレクトリに依存させない。

[AGENTS.md](../../../AGENTS.md) を読み、既存の [run_analysis.py](../../../scripts/run_analysis.py) に入力コピー・実行・保存を任せる。解析ロジックや通常運用の定義ファイルをその場で書き換えない。

## 依頼と設定を確定する

- 新しい解析には入力kファイルのパスを使う。登録候補は `processes/*/process.json`。利用者指定を優先し、未指定なら設定済みの候補が1つの場合に限りそれを選んで伝える。複数候補なら解析種類を確認する。`_template` は選ばない。
- 「準備だけ」なら `--prepare-only` を使い、GHもComputeも起動しない。「結果を見せて」なら指定runを読むだけとし、新規解析を始めない。run指定がなければ入力・時刻から特定し、曖昧なら確認する。
- `config/user-config.json` と選択プロセスの設定を読む。GHファイルの存在、単一のkファイル、既定600秒の応答待ちを確認する。`*INCLUDE` 系の入力は初版の対象外なので、無断で結合・除去しない。
- 設定不足・Compute未起動・日本語パスへの対応が必要なときだけ [references/setup.md](references/setup.md) を読む。不足するパスや条件は確認する。ソースコードや追加のdone出力を要求しない。

## 1回だけ実行する

通常実行前に `workspace/.analysis.lock` の有無を確認する。存在する場合はそのrunの状態を調べ、ロックを削除して新しい解析を始めない。ユーザーが依頼済みの解析に改めて一律の承認を要求する必要はない。

配布ルートを作業ディレクトリにし、利用可能なPython 3.11以降の実行ファイルで起動する。利用者指定パスをシェルのコードとして展開せず、引数として引用する。

```powershell
python scripts/run_analysis.py --process process-test --input 'E:/data/model.k'
```

`process-test` と入力パスは選択した値に置き換える。別設定ファイルなら `--config`、準備のみなら `--prepare-only` を付ける。準備のみのrunを後から再利用するCLIはないため、実行依頼時は新しいrunが作られる。

実行ツールがセッションIDを返したら、同じセッションの終了を待つ。表示上の待機終了を解析失敗とみなしてコマンドを再発行しない。長時間の待機では状況を適宜伝える。GHの画面操作やソルバーの直接起動で迂回しない。

## 応答と成果物を確認する

終了時のJSONにある `run_directory` を使い、そのrunの `exchange/run.json` を読む。過去の成功runや、単に最新のフォルダーへ置き換えない。終了コードだけで成功を判定しない。

| 状態 | 扱い |
|---|---|
| `prepared` | コピーと準備のみ。解析実行済みとは伝えない |
| `succeeded` | GH応答を受信したため成功扱い。ソルバー内部の正常終了を検証したとは述べない |
| `failed_before_solve` | 実行要求前の失敗。記録された原因を伝える |
| `unknown` | 通信失敗・タイムアウト等で結果不明。再送・強制終了・ロック解除を自動で行わない |
| `integrity_error` | 定義または入力の変更を検出。正常完了とせず、復元や上書きをしない |
| `preparing` / `checking_connection` / `running` | 途中状態。プロセスが終了済みでも成功を推定しない |

`post_status` も確認する。`error` / `blocked` はGHの成功と分けて伝え、`pending_implementation` はポスト処理未実装を意味する。`gh_errors`・`gh_warnings` があれば隠さず報告するが、応答受信を成功とする利用者指定の基準を独自に変更しない。

結果案内は `raw/solver/` を実際に列挙して行う。`d3plot` が存在する場合はその絶対パスと同じフォルダーの分割ファイルを案内する。存在しない結果は生成済みと説明しない。ファイル不足はGH応答の有無と分けて伝え、空ファイル等で補わない。

最終回答には入力名、process-id、run-id、実行状態、結果フォルダーへのリンクを含める。成功根拠は「GH応答の受信」。詳細な実行記録が必要なら `exchange/run.json`、エラーなら `logs/error.txt` へ案内する。

## 現在の到達点

このSkillの自動フローはRaw保存と結果案内まで。別途依頼されたHTMLレポートの作成には [レポート記載基準](../../../docs/report-guidelines.md) と `scripts/render_report.py` を使用できる。専門知識による評価、数値抽出、ポスト処理の自動連結は未実装。未整備の評価基準で良否を断定しない。将来の拡張や配布方法は [README.md](../../../README.md) を参照する。
